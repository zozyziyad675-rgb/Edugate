🧱 Limited-Access Data Structures (The Big Picture)

The access rule is part of the data structure definition. Imagine four different "boxes":

· Stack 🥞 → Insert at TOP, Remove from TOP, Rule: LIFO
· Queue 🚶‍♂️🚶‍♀️ → Insert at REAR, Remove from FRONT, Rule: FIFO
· Priority Queue 🚑 → Remove highest priority; tie rule may preserve arrival order
· Circular Queue 🔄 → FIFO in a fixed array; indices wrap around

Restricted access gives predictable behavior that directly matches many real systems.

⚠️ Key distinction: The ADT defines what operations are legal; the implementation defines how they are performed. Always analyze the implementation, not only the ADT name.

Core ADT Operations & Boundary Conditions

Structure Insert Remove Inspect Boundary Condition
Stack Push(x) Pop() Peek() underflow; fixed stack may overflow
Queue Enqueue(x) Dequeue() Peek() underflow; bounded queue may overflow
Priority Queue Enqueue(x,p) DequeueHighest() PeekHighest() empty structure
Circular Queue Enqueue(x) Dequeue() Peek() count=0 empty; count=capacity full

· Underflow ⬇️ = Removing or inspecting when no element exists.
· Overflow ⬆️ = Adding to a fixed-capacity structure that is already full.

❓ Central question: Why does "most recent first" make a stack the correct structure?

🥞 The Stack Concept: LIFO

Last In, First Out — think of a stack of plates 🍽️. The last plate you put on top is the first one you take off.

Visualize:

[ 30 ]  ← TOP
[ 20 ]
[ 10 ]
 BOTTOM
The Operations:

· Push ➕ → Adds a new item at the top. Push(40) makes 40 the next item to leave.
· Pop ➖ → Removes and returns the top item. Pop() returns 30 in the shown stack.
· Peek 👀 → Returns the top item without removal. The stack remains unchanged.
· IsEmpty ❓ → Tests whether the stack has no items. Required before safe Pop/Peek.

🔑 Only the TOP is directly accessible through the Stack ADT.

📊 Trace: State After Every Operation

Operation Stack (bottom → top) Return Cost
Push(10) [10] — O(1)
Push(20) [10, 20] — O(1)
Push(30) [10, 20, 30] — O(1)
Peek() [10, 20, 30] 30 O(1)
Pop() [10, 20] 30 O(1)
Pop() [20] 20 O(1)

📝 Trace rule: Record the state after the operation, not before it.
⚠️ Error case: Pop/Peek on an empty stack must be rejected.

🧮 Array-Based Stack: Algorithm

A top index turns one array end into the stack interface.

Push pseudocode:

Push(S, item)
    if top = capacity - 1
        report overflow
    top <- top + 1
    data[top] <- item
Pop pseudocode:

Pop(S)
    if top = -1
        report underflow
    item <- data[top]
    top <- top - 1
    return item
⚡ No loop depends on n ⇒ Push and Pop are O(1).

💻 C# Implementation (Encapsulation Protects Invariants)

public class ArrayStack<T>
{
    private readonly T[] data;
    private int top = -1;

    public ArrayStack(int capacity) => data = new T[capacity];
    public bool IsEmpty() => top == -1;
    public bool IsFull() => top == data.Length - 1;

    public void Push(T item)
    {
        if (IsFull()) throw new InvalidOperationException("Stack overflow");
        data[++top] = item;
    }

    public T Pop()
    {
        if (IsEmpty()) throw new InvalidOperationException("Stack underflow");
        return data[top--];
    }

    public T Peek()
    {
        if (IsEmpty()) throw new InvalidOperationException("Stack empty");
        return data[top];
    }
}
🛡️ Encapsulation protects the top index and capacity rules.

🐍 Python Stack & Built-In Collections

Python wrapper:

class Stack:
    def __init__(self):
        self._items = []

    def push(self, item):
        self._items.append(item)

    def pop(self):
        if not self._items:
            raise IndexError("Stack underflow")
        return self._items.pop()

    def peek(self):
        if not self._items:
            raise IndexError("Stack empty")
        return self._items[-1]
C# built-in Stack<T>:

stack.Push(10);
stack.Push(20);
stack.Push(30);

Console.WriteLine(stack.Pop());  // 30

🔄 Application 1: String Reversal

A stack naturally reverses insertion order.

Reverse(text)
    create empty stack
    for each character ch in text
        Push(ch)
    result <- empty
    while stack is not empty
        result <- result + Pop()
    return result
· Input: DATA
· Output: ATAD

⚡ n pushes + n pops = 2n operations → O(n) time; stack space O(n).

🔗 Application 2: Balanced Parentheses

The most recent unmatched opening bracket must be checked first — perfect for LIFO.

def balanced(text):
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for ch in text:
        if ch in '([{':
            stack.append(ch)
        elif ch in ')]}':
            if not stack or stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0
· ✅ Valid: (a + [b * c])
· ❌ Invalid: ([a + b])
· Complexity: One scan → O(n) time; worst-case stack → O(n) space.

] Pop [ [(] match

🔑 Invariant: The stack stores unmatched opening brackets only.
⚠️ Failure rule: Wrong type or empty stack during close → invalid.

· Redo stack → Undo pushes the reversed action onto Redo. Redo pops it back to Undo.

🗼 Application 4: Tower of Hanoi (Recursive Stack Application)

Each rod is naturally represented by a stack.

Recursive algorithm:

Move(n, from, to, auxiliary)
    if n = 0
        return
    Move(n-1, from, auxiliary, to)
    to.Push(from.Pop())
    Move(n-1, auxiliary, to, from)
· Rule 1: Move only the top disc of a rod.
· Rule 2: Never place a larger disc on a smaller disc.

Solved Trace: 3 Discs (minimum 2³ − 1 = 7 moves)

Move From To Disc
1 A C 1
2 A B 2
3 C B 1
4 A C 3
5 B A 1
6 B C 2
7 A C 1

📈 T(n) = 2T(n−1) + 1 → 2ⁿ − 1 moves → O(2ⁿ) time; recursion depth O(n).

🚶‍♂️ The Queue Concept: FIFO

First In, First Out — think of a line at a coffee shop ☕. The first person in line gets served first.

Visualize:

FRONT ↓                         REAR ↓
[  A  ][  B  ][  C  ]
The Operations:

· Enqueue(x) ➕ → Add the new item at the rear.
· Dequeue() ➖ → Remove and return the item at the front.
· Peek() 👀 → Inspect the front item without removing it.

📊 Queue Operations & Trace

Operation Front → Rear Return Typical Cost
Enqueue(A) [A] — O(1)
Enqueue(B) [A, B] — O(1)
Enqueue(C) [A, B, C] — O(1)
Peek() [A, B, C] A O(1)
Dequeue() [B, C] A O(1)
Enqueue(D) [B, C, D] — O(1)

⚠️ An efficient queue should NOT shift all remaining elements after every Dequeue.

🔑 Choose operations that use opposite ends efficiently: rear insertion, front removal.

⚠️ Complexity Trap: Python list as a Queue

Correct FIFO output does NOT guarantee an efficient implementation!

q = []
q.append(item)     # rear insertion
x = q.pop(0)       # front removal
· Enqueue: append at end → O(1) amortized ✅
· Dequeue: pop(0) shifts later elements → O(n) ❌

🧠 Data-structure analysis asks both: "Does it work?" and "How does the cost grow?"

🔗 Linked Queue

Front removes; rear appends.

FRONT ↓        REAR ↓
[10] → [20]
· front → Reference to the node that will be removed next.
· rear → Reference to the last node; new nodes are linked here.
· Empty invariant: front == null and rear == null.

C# Implementation — both operations O(1):

`csharp
class QNode<T>
{
    public T Data;
    public QNode<T>? Next;
    public QNode(T data) => Data = data;
}

class LinkedQueue<T>
{
    private QNode<T>? front;
    private QNode<T>? rear;
public void Enqueue(T item)
    {
        QNode<T> n = new(item);
        if (rear == null) front = rear = n;
        else { rear.Next = n; rear = n; }
    }

    public T Dequeue()
    {
        if (front == null) throw new InvalidOperationException("Queue empty");
        T value = front.Data;
        front = front.Next;
        if (front == null) rear = null;
        return value;
    }
}

Python Implementation:

python
class Node:
    def init(self, data):
        self.data = data
        self.next = None

class LinkedQueue:
    def init(self):
        self.front = None
        self.rear = None

    def enqueue(self, item):
        n = Node(item)
        if self.rear is None:
            self.front = self.rear = n
        else:
            self.rear.next = n
            self.rear = n

    def dequeue(self):
        if self.front is None:
            raise IndexError("Queue empty")
        value = self.front.data
        self.front = self.front.next
        if self.front is None:
            self.rear = None
        return value

🚑 Priority Queue Concept

Priority first; arrival order can break ties.

Arrival Item Priority
1 Normal-A 2
2 Gold-A 0
3 Normal-B 2
4 Silver-A 1
5 Gold-B 0

Service order: Gold-A → Gold-B → Silver-A → Normal-A → Normal-B

🎯 Convention used here: 0 = highest priority; larger values = lower priority. (Think: 0 = VIP, like a gold card!)

⚖️ Stable Priority: Preserve Arrival Order Within a Priority

Priority and sequence number form a useful comparison key.

· Primary key → priority
· Tie-break key → arrival order / sequence number

Conceptual record:

record = (priority, arrival_order, item)

compare priority first
    if equal:
        compare arrival_order
`

🤝 Stable service avoids reordering customers who have equal priority. (Think: two Gold members both arrive — the one who came first should still go first!)

⚖️ Priority Queue Implementation Trade-Offs

The ADT is fixed; the operation cost depends on representation.

Implementation Enqueue Dequeue highest Peek highest Idea
Sorted sequence O(n) O(1)* O(1) pay during insertion
Unsorted sequence O(1) O(n) O(n) pay during removal
Binary heap O(log n) O(log n) O(1) balanced cost

*Assumes highest-priority end can be removed efficiently; a Python list.pop(0) itself shifts elements.

📥 Sorted Priority Queue: Insertion Algorithm

Find the correct position using priority AND arrival order.

Enqueue(item, priority)
    record <- (priority, sequence, item)
    sequence <- sequence + 1

    i <- 0
    while i < count and items[i] <= record
        i <- i + 1

    insert record at i
· Search: May scan O(n) positions.
· Array/list insert: May shift O(n) items.
· Overall Enqueue: O(n).

💻 Implementations

Python educational version:

class PriorityQueue:
    def __init__(self):
        self.items = []
        self.order = 0

    def enqueue(self, value, priority):
        rec = (priority, self.order, value)
        self.order += 1
        i = 0
        while i < len(self.items) and self.items[i] <= rec:
            i += 1
        self.items.insert(i, rec)

    def dequeue(self):
        if not self.items:
            raise IndexError("empty")
        return self.items.pop(0)[2]
C# built-in style:

var pq = new PriorityQueue<string, int>();
pq.Enqueue("Normal-A", 2);
pq.Enqueue("Gold-A", 0);
pq.Enqueue("Silver-A", 1);

Console.WriteLine(pq.Dequeue()); // Gold-A

⚠️ Priority Design Issue: Starvation and Aging

Correct priority order may still create fairness problems!

· Starvation 😢 → A low-priority request may wait a very long time if higher-priority work keeps arriving.
· Aging 👴 → Gradually increase the effective priority of items that have waited too long.
· Quota rule 📊 → After several urgent items, force service of an older normal item.
· Maximum wait ⏰ → Escalate an item after a defined waiting-time threshold.

🧠 Data structure choice and service policy are related but NOT identical design decisions.

📊 Complexity Summary (State the Representation First!)

· Sorted sequence: Enqueue O(n), Dequeue O(1)*, Peek O(1)
· Unsorted sequence: Enqueue O(1), Dequeue O(n), Peek O(n)
· Binary heap: Enqueue O(log n), Dequeue O(log n), Peek O(1)

🎯 The same Priority Queue ADT can have different performance profiles.

· Choose based on which operation dominates the workload.
· For large general-purpose priority queues, heaps are common because they balance insertion and removal.

❓ Central question: How can an array queue avoid shifting after every Dequeue?

🔄 The Ring-Buffer Model

A fixed array is reused by wrapping the indices.

front
 ↓
[ A ][ B ][ C ][ — ][ — ]
  0    1    2    3    4
                  ↑
                 rear
♻️ Array cells are reused; no left-shifting is required.

📋 Invariants (The Rules)

Field/Condition Meaning
front index of next item to dequeue
rear index of next position to enqueue
count number of stored items
capacity length of storage array
Empty count == 0
Full count == capacity

✅ After every Enqueue/Dequeue, check 0 ≤ count ≤ capacity and both indices stay in range.

🔢 Modulo Arithmetic: next = (current + 1) % capacity

nextIndex = (currentIndex + 1) % capacity

capacity current (current+1)%capacity Meaning
5 0 1 move to next cell
5 3 4 move to last cell
5 4 0 wrap to first cell
8 7 0 wrap to first cell

🧮 Why modulo works: The remainder after division by capacity is always a valid index from 0 to capacity−1. Think of a clock: after 12 comes 1 again! 🕐

💻 C# Implementation — O(1) Enqueue/Dequeue

public class CircularQueue<T>
{
    private readonly T[] items;
    private int front = 0, rear = 0, count = 0;

    public CircularQueue(int capacity) => items = new T[capacity];
    public bool IsEmpty() => count == 0;
    public bool IsFull() => count == items.Length;

    public void Enqueue(T item)
    {
        if (IsFull()) throw new InvalidOperationException("Queue full");
        items[rear] = item;
        rear = (rear + 1) % items.Length;
        count++;
    }

    public T Dequeue()
    {
        if (IsEmpty()) throw new InvalidOperationException("Queue empty");
        T value = items[front];
        front = (front + 1) % items.Length;
        count--;
        return value;
    }
}
🐍 Python Implementation

class CircularQueue:
    def __init__(self, capacity):
        self.items = [None] * capacity
        self.front = 0
        self.rear = 0
        self.count = 0

    def enqueue(self, item):
        if self.count == len(self.items):
            raise OverflowError("Queue full")
        self.items[self.rear] = item
        self.rear = (self.rear + 1) % len(self.items)
        self.count += 1

    def dequeue(self):
        if self.count == 0:
            raise IndexError("Queue empty")
        value = self.items[self.front]
        self.front = (self.front + 1) % len(self.items)
        self.count -= 1
        return value

⚔️ Circular Queue vs. Shifting Array Queue

Same FIFO behavior, very different Dequeue cost!

· Naive shifting array ❌ → Dequeue removes index 0. All remaining elements shift left. Worst-case Dequeue: O(n).
· Circular array ✅ → Dequeue reads items[front]. front advances with modulo. Dequeue: O(1).

🧠 Changing the representation removes unnecessary element movement.
Both are FIFO. The circular representation is designed for repeated fixed-capacity enqueue/dequeue.

🌐 Applications

· Streaming buffer 📺 → Store a bounded window of arriving data.
· Device/network buffer 🌐 → Reuse fixed storage as messages are consumed.
· Roller-coaster queue 🎢 → Limited number of carts/slots.
